# 6. Общая идея лабораторной

Лабораторная про **байесовский анализ** и **вероятностное программирование**.

Обычная статистика часто пытается найти одно «лучшее» значение параметра. Байесовский подход работает иначе: он говорит, что параметр неизвестен, поэтому мы описываем его **распределением вероятностей**.

Главная схема такая:

```text
априорное знание + данные -> апостериорное распределение
```

На языке формулы:

```text
posterior ∝ likelihood × prior
```

То есть:

- `prior` / априорное распределение — что мы думаем о параметре до данных;
- `likelihood` / правдоподобие — насколько хорошо параметр объясняет наблюдаемые данные;
- `posterior` / апостериорное распределение — что мы думаем о параметре после учёта данных.

В PyMC это записывается почти как математическая модель:

```python
with pm.Model() as model:
    parameter = pm.Normal("parameter", mu=0, sigma=10)
    observed = pm.Normal("observed", mu=parameter, sigma=1, observed=data)
    trace = pm.sample()
```

`trace` — это результат сэмплирования, то есть набор значений параметров, которые PyMC считает правдоподобными после учёта данных.

# 8. Что такое основные команды PyMC и ArviZ

## `with pm.Model() as model:`

Так создаётся модель. Всё, что внутри этого блока, относится к одной вероятностной модели.

## `pm.Beta(...)`

Бета-распределение. Обычно используется для вероятностей от 0 до 1. Например, вероятность орла у монеты или конверсия в A/B-тесте.

## `pm.Bernoulli(...)`

Распределение для события 0/1. Например:

- орёл / решка;
- повреждение / нет повреждения;
- класс 0 / класс 1.

## `pm.Binomial(...)`

Распределение для числа успехов из `n` попыток. Например, 30 конверсий из 100 пользователей.

## `pm.Normal(...)`

Нормальное распределение. Часто используется для коэффициентов регрессии.

## `pm.HalfNormal(...)`

Половинное нормальное распределение. Используется для параметров, которые не могут быть отрицательными, например для `sigma`.

## `pm.StudentT(...)`

Распределение Стьюдента. Оно похоже на нормальное, но лучше переносит выбросы. Поэтому используется в робастной регрессии.

## `pm.sample(...)`

Запускает сэмплирование. PyMC подбирает много возможных значений параметров, которые согласуются с данными.

## `az.summary(...)`

Показывает таблицу по параметрам:

- `mean` — среднее значение параметра;
- `sd` — стандартное отклонение;
- `hdi_3%` и `hdi_97%` — границы 94% HDI-интервала;
- `ess_bulk`, `ess_tail` — эффективный размер выборки;
- `r_hat` — диагностика сходимости. Хорошо, когда примерно `1.0`.

## `az.plot_trace(...)`

Показывает, как сэмплер ходил по значениям параметров. Нужно, чтобы проверить, не «залипла» ли модель.

## `az.plot_posterior(...)`

Показывает апостериорное распределение параметров: какие значения наиболее вероятны после учёта данных.

## `az.plot_ppc(...)`

Posterior predictive check. Проверяет, похожи ли данные, сгенерированные моделью, на реальные данные.

# 9. Разбор каждого ноутбука

## 9.1. `01_coin_toss.ipynb.ipynb` — монета и байесовский вывод

### Что это за часть задания

Это соответствует базовому байесовскому выводу с одним параметром и примеру с подбрасыванием монеты.

### Что происходит

Есть данные:

```python
data = np.array([1, 0, 1, 1, 1, 0, 1, 1, 0, 1])
```

Здесь:

- `1` — выпал орёл;
- `0` — выпала решка.

Всего 10 бросков, орлов 7.

Главный неизвестный параметр:

```python
theta = pm.Beta("theta", alpha=1, beta=1)
```

`theta` — вероятность выпадения орла.

`Beta(1, 1)` — нейтральное априорное распределение. Оно означает: до эксперимента мы не делаем сильного предположения, честная монета или нет.

Данные подключаются так:

```python
y = pm.Bernoulli("y", p=theta, observed=data)
```

То есть каждый бросок — это событие Бернулли с вероятностью успеха `theta`.

### Как читать результат

`az.summary(trace)` показывает, какое значение `theta` получилось после учёта данных. В уже выполненном ноутбуке среднее было около `0.671`. Это логично: в данных 7 орлов из 10, то есть грубая частота равна `0.7`, но байесовская оценка немного сглажена априорным распределением.

### Что сказать своими словами

> Здесь мы оцениваем вероятность выпадения орла. До данных считаем все значения от 0 до 1 одинаково возможными. Потом учитываем 10 наблюдений, где 7 раз выпал орёл. В результате получаем не одно число, а распределение возможных значений вероятности орла.

## 9.2. `02_linear_regression.ipynb` — байесовская линейная регрессия

### Что это за часть задания

Это простая линейная регрессия из байесовского анализа.

### Что происходит

Сначала генерируются искусственные данные:

```python
x = np.linspace(0, 10, 100)
y = 1 + 2 * x + np.random.normal(0, 2, size=len(x))
```

Настоящая зависимость примерно такая:

```text
y = 1 + 2x + шум
```

Модель пытается восстановить коэффициенты:

```python
alpha = pm.Normal("alpha", mu=0, sigma=10)
beta = pm.Normal("beta", mu=0, sigma=10)
sigma = pm.HalfNormal("sigma", sigma=5)
mu = alpha + beta * x
```

Где:

- `alpha` — свободный член, пересечение с осью y;
- `beta` — наклон прямой;
- `sigma` — уровень шума;
- `mu` — предсказанное среднее значение y.

Наблюдения подключаются через нормальное распределение:

```python
y_obs = pm.Normal("y_obs", mu=mu, sigma=sigma, observed=y)
```

### Как читать результат

В выполненном ноутбуке примерно получилось:

- `alpha ≈ 0.66`;
- `beta ≈ 2.03`;
- `sigma ≈ 1.85`.

Это нормально: данные были созданы как `1 + 2x + шум`, поэтому модель почти восстановила коэффициент при `x`.

### Зачем строятся графики

Графики показывают:

1. Исходные точки.
2. Среднюю байесовскую линию регрессии.
3. Несколько возможных линий из апостериорного распределения.
4. 94% HDI — область неопределённости вокруг линии.

### Что сказать своими словами

> В обычной регрессии мы получили бы одну прямую. В байесовской регрессии мы получаем распределения для коэффициентов `alpha`, `beta` и `sigma`, поэтому можем видеть не только лучшую линию, но и неопределённость вокруг неё.

## 9.3. `03_robust_linear_regression_anscombe.ipynb` — робастная регрессия на Anscombe

### Что это за часть задания

Это вариант робастной регрессии «из книги» / на готовом датасете.

### Что за датасет

`anscombe.csv` — это квартет Энскомба. В нём несколько наборов данных, у которых похожие простые статистики, но разные графики. Поэтому его часто используют, чтобы показать: нельзя смотреть только на средние и корреляции, нужно строить графики.

В ноутбуке берётся набор:

```python
data_iii = df[df["dataset"] == "III"].copy()
```

У этого набора есть выброс, поэтому обычная линейная регрессия может вести себя хуже.

### Что такое робастная регрессия

Робастная регрессия — это регрессия, которая меньше ломается из-за выбросов.

Вместо нормального распределения используется распределение Стьюдента:

```python
y_obs = pm.StudentT(
    "y_obs",
    nu=3,
    mu=mu,
    sigma=sigma,
    observed=y
)
```

У распределения Стьюдента более «тяжёлые хвосты». Простыми словами: оно допускает, что некоторые точки могут быть далеко от линии, и не заставляет модель сильно подстраиваться под один выброс.

### Зачем масштабируется `x`

```python
x_scaled = (x - x_mean) / x_std
```

Масштабирование делает `x` более удобным для модели: среднее около 0, стандартное отклонение около 1. Это часто помогает сэмплеру работать стабильнее.

### Как читать результат

- `alpha` — уровень линии при среднем `x`;
- `beta` — наклон линии;
- `sigma` — разброс точек вокруг линии.

`az.plot_ppc` проверяет, может ли модель генерировать данные, похожие на реальные.

### Что сказать своими словами

> Здесь используется робастная линейная регрессия. Она отличается от обычной тем, что ошибки моделируются распределением Стьюдента, а не нормальным распределением. Это нужно, чтобы выбросы не слишком сильно портили оценку линии.

## 9.4. `04_robust_linear_regression_own_data.ipynb` — робастная регрессия на своём датасете

### Что это за часть задания

Это второй вариант робастной регрессии — не на Anscombe, а на другом датасете.

В исходной версии был датасет `tips` из Seaborn. В исправленной версии используется локальный файл:

```python
tips = pd.read_csv("../data/own_robust_data.csv")
```

### Что моделируется

Модель смотрит зависимость:

```text
tip от total_bill
```

То есть насколько размер чаевых зависит от суммы счёта.

```python
x = tips["total_bill"].values
y = tips["tip"].values
```

`total_bill` масштабируется, затем строится робастная регрессия через `StudentT`.

### Почему снова `StudentT`

В реальных данных по чаевым бывают нетипичные случаи: кто-то оставил слишком много или слишком мало. Поэтому робастная модель полезна: она не так сильно реагирует на необычные точки.

### Что сказать своими словами

> Это тот же принцип, что в предыдущем ноутбуке, но на другом датасете. Мы оцениваем зависимость чаевых от суммы счёта и используем распределение Стьюдента, чтобы модель была устойчивее к выбросам.

## 9.5. `05_logistic_regression_iris.ipynb` — логистическая регрессия на Iris

### Что это за часть задания

Это логистическая регрессия из раздела об обобщённых линейных моделях.

### Что за данные

Используется готовый датасет Iris:

```python
iris = load_iris(as_frame=True)
df = iris.frame
```

Потом оставляются только два класса:

```python
df = df[df["target"] != 2].copy()
```

То есть задача становится бинарной: класс `0` или класс `1`.

В качестве признака берётся длина лепестка:

```python
x = df["petal length (cm)"].values
y = df["target"].values
```

### Почему нужна логистическая регрессия

Обычная линейная регрессия предсказывает любое число, например `-2`, `0.5`, `10`. Но здесь нужно предсказать вероятность класса, а вероятность должна быть от 0 до 1.

Поэтому используется сигмоида:

```python
p = pm.Deterministic("p", pm.math.sigmoid(mu))
```

Сигмоида переводит любое число в диапазон от 0 до 1.

### Модель

```python
alpha = pm.Normal("alpha", mu=0, sigma=10)
beta = pm.Normal("beta", mu=0, sigma=10)
mu = alpha + beta * x_scaled
p = sigmoid(mu)
y_obs = pm.Bernoulli("y_obs", p=p, observed=y)
```

Где:

- `alpha` — базовый уровень;
- `beta` — влияние длины лепестка;
- `p` — вероятность класса 1;
- `Bernoulli` — потому что ответ бинарный: 0 или 1.

### Что сказать своими словами

> Логистическая регрессия нужна, когда целевая переменная — это класс 0/1. Модель строит не прямую для `y`, а вероятность принадлежности к классу. Для этого линейная комбинация признаков проходит через сигмоиду.

## 9.6. `06_ab_testing_book.ipynb` — A/B-тестирование по примеру из книги

### Что это за часть задания

Это вероятностное программирование и байесовское A/B-тестирование.

### Что происходит

Есть две версии страницы или продукта:

```python
conversions_A = 30
total_A = 100

conversions_B = 40
total_B = 100
```

В группе A — 30 конверсий из 100. В группе B — 40 из 100.

Неизвестные параметры:

```python
p_A = pm.Beta("p_A", alpha=1, beta=1)
p_B = pm.Beta("p_B", alpha=1, beta=1)
```

Где:

- `p_A` — настоящая конверсия группы A;
- `p_B` — настоящая конверсия группы B.

Данные описываются биномиальным распределением:

```python
obs_A = pm.Binomial("obs_A", n=total_A, p=p_A, observed=conversions_A)
obs_B = pm.Binomial("obs_B", n=total_B, p=p_B, observed=conversions_B)
```

Разница конверсий:

```python
delta = pm.Deterministic("delta", p_B - p_A)
```

### Как читать результат

В выполненном ноутбуке было:

```text
P(B > A) ≈ 0.931
```

То есть по модели вероятность того, что B лучше A, около 93.1%.

Но важно: это не значит, что B точно лучше. Это значит, что с учётом модели и данных B выглядит заметно вероятнее лучшим вариантом.

### Что сказать своими словами

> В байесовском A/B-тесте мы оцениваем не просто две частоты, а распределения возможных конверсий для A и B. Потом смотрим распределение разности `p_B - p_A` и считаем вероятность, что эта разность больше нуля.

## 9.7. `07_ab_testing_custom.ipynb` — A/B-тестирование на своём датасете

### Что это за часть задания

Это второй датасет для вероятностного программирования.

Файл:

```text
data/custom_ab_data.csv
```

Содержит:

```text
group,conversions,total
A,120,1500
B,145,1500
```

То есть:

- A: 120 конверсий из 1500;
- B: 145 конверсий из 1500.

### Что происходит

Модель полностью такая же, как в предыдущем ноутбуке:

```python
p_A ~ Beta(1, 1)
p_B ~ Beta(1, 1)
conversions_A ~ Binomial(total_A, p_A)
conversions_B ~ Binomial(total_B, p_B)
delta = p_B - p_A
```

### Как читать результат

В выполненном ноутбуке было:

```text
P(B > A) ≈ 0.948
```

То есть вариант B снова выглядит лучше.

При этом апостериорный интервал для `delta` может частично заходить около 0. Поэтому лучше формулировать аккуратно: B вероятно лучше, но неопределённость всё ещё есть.

### Что сказать своими словами

> Здесь тот же байесовский A/B-тест, но на другом наборе данных. Мы не просто сравниваем 8% и 9.67%, а учитываем неопределённость этих оценок и считаем вероятность того, что B реально лучше A.

## 9.8. `08_challenger_disaster.ipynb` — катастрофа Challenger

### Что это за часть задания

Это пример вероятностного программирования с логистической регрессией.

### Что за данные

Есть температуры запусков и информация, было ли повреждение:

```python
temperature = np.array([...])
damage = np.array([...])
```

Где:

- `temperature` — температура при запуске;
- `damage` — было повреждение уплотнительных колец или нет: 1 / 0.

### Что моделируется

Модель оценивает вероятность повреждения в зависимости от температуры.

```python
mu = alpha + beta * x_scaled
p = sigmoid(mu)
y_obs = Bernoulli(p, observed=y)
```

Если `beta` отрицательный, значит при росте температуры вероятность повреждения уменьшается. В выполненном ноутбуке `beta` был отрицательным, поэтому модель показывает: при низкой температуре риск повреждения выше.

### Что сказать своими словами

> Здесь логистическая регрессия используется для оценки вероятности аварийного события. Целевая переменная бинарная: повреждение было или не было. Модель показывает, как температура влияет на вероятность повреждения.

## 9.9. `09_advanced_ab_testing.ipynb` — продвинутое A/B-тестирование

### Что это за часть задания

Это продолжение вероятностного программирования и A/B-тестирования: не только вероятность, что B лучше, но и оценка потерь / ожидаемой выручки.

### Часть 1. A/B-тест и функция потерь

Сначала снова сравниваются A и B:

```python
conversions_A = 120
total_A = 1500

conversions_B = 145
total_B = 1500
```

Считается:

```python
delta = p_B - p_A
```

Потом считаются ожидаемые потери:

```python
loss_A = np.mean(np.maximum(delta_samples, 0))
loss_B = np.mean(np.maximum(-delta_samples, 0))
```

Смысл:

- если выбрать A, а B на самом деле лучше, мы теряем разницу;
- если выбрать B, а A на самом деле лучше, мы тоже теряем разницу;
- выбираем вариант с меньшей ожидаемой потерей.

В выполненном ноутбуке было примерно:

```text
Expected loss for choosing A: 0.01703
Expected loss for choosing B: 0.00027
Вариант B предпочтительнее.
```

То есть выбирать B рискованно меньше.

### Часть 2. Ожидаемая выручка и распределение Дирихле

Дальше рассматривается ситуация, где пользователь может выбрать один из тарифов:

```python
N_79 = 10
N_49 = 46
N_25 = 80
N_0 = 864
```

Это значит: из 1000 пользователей кто-то выбрал тариф за 79, кто-то за 49, кто-то за 25, а большинство ничего не купили.

Используется распределение Дирихле:

```python
posterior_samples = dirichlet(posterior_parameters, size=10000)
```

Дирихле — это обобщение бета-распределения на несколько вероятностей. Бета подходит для двух исходов, а Дирихле — когда исходов больше двух.

Потом считается ожидаемая выручка:

```python
def expected_revenue(P):
    return 79 * P[:, 0] + 49 * P[:, 1] + 25 * P[:, 2] + 0 * P[:, 3]
```

В выполненном ноутбуке средняя ожидаемая выручка была около `5.17`.

### Что сказать своими словами

> В этом ноутбуке A/B-тест доводится до принятия решения. Мы смотрим не только на вероятность того, что B лучше, но и на ожидаемую потерю от неправильного выбора. Затем отдельно моделируется ожидаемая выручка через распределение Дирихле, потому что вариантов выбора больше двух.

# 12. Что именно говорить при защите

Короткий общий вариант:

> В лабораторной я разбираю несколько байесовских моделей. В отличие от классического подхода, здесь параметры не считаются фиксированными неизвестными числами, а описываются распределениями. Сначала задаётся априорное распределение, затем добавляются данные через функцию правдоподобия, после чего PyMC с помощью MCMC строит апостериорное распределение. Результаты анализируются через ArviZ: summary, trace plot, posterior plot и posterior predictive check.

Про монету:

> Вероятность орла моделируется параметром `theta`. Априорное распределение — `Beta(1, 1)`, данные — броски 0/1, наблюдения задаются через `Bernoulli`. После сэмплирования получаем распределение вероятности орла.

Про линейную регрессию:

> В линейной регрессии оцениваются `alpha`, `beta` и `sigma`. Байесовский подход даёт не одну линию, а распределение возможных линий и интервал неопределённости.

Про робастную регрессию:

> Робастная регрессия использует распределение Стьюдента для ошибок. Оно менее чувствительно к выбросам, поэтому линия не так сильно искажается отдельными нетипичными точками.

Про логистическую регрессию:

> Логистическая регрессия используется для бинарной целевой переменной. Линейная комбинация признаков проходит через сигмоиду, поэтому результат становится вероятностью от 0 до 1.

Про A/B-тест:

> В A/B-тесте конверсии A и B моделируются через бета-биномиальную схему. Для каждой группы оценивается распределение конверсии, а затем считается распределение разности `p_B - p_A` и вероятность `P(B > A)`.

Про продвинутое A/B:

> Там добавляется функция потерь: мы выбираем не только по вероятности, но и по ожидаемому ущербу от неправильного решения. Также используется распределение Дирихле для нескольких вариантов покупки и оценки ожидаемой выручки.

# 15. Если надо быстро понять суть всей лабораторной

Вся лабораторная строится вокруг одной идеи: **неизвестные параметры описываются распределениями**.

- В монете неизвестна вероятность орла.
- В линейной регрессии неизвестны коэффициенты прямой.
- В робастной регрессии то же самое, но модель устойчивее к выбросам.
- В логистической регрессии неизвестна связь признака с вероятностью класса.
- В A/B-тестировании неизвестны настоящие конверсии вариантов A и B.
- В продвинутом A/B мы не только сравниваем варианты, но и оцениваем потери и выручку.

Главная практическая польза байесовского подхода: он показывает не только «лучший ответ», но и **насколько мы в этом ответе уверены**.
