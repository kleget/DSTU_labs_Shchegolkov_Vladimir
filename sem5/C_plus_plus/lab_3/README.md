# Лабораторная № 3. Функции и рекурсия — вариант 12

Этот README объясняет текущие `lab.h`, `lab.cpp` и `main.cpp`: что делает каждая содержательная строка, как файлы связываются и как восстановить алгоритмы самостоятельно. Исходный код при подготовке документа не изменялся.

Сначала разберись с устройством трёх файлов и ссылками. Затем пройди вычисление корней и раскрутку рекурсии на бумаге. В конце есть сборка, контрольные примеры и вопросы для подготовки к защите.

## 1. Что требуется по методичке

Источник: [методичка](../Методичка_Программирование_С++_лаб_3_1.pdf), требования перед таблицей на странице 23, вариант 12 на странице 25.

- Вводить необходимые параметры с клавиатуры.
- Выводить результаты в консоль.
- Вынести вычисления в функции; корни уравнений находить в функции.
- Второе задание выполнить с помощью рекурсивной функции.
- Использовать минимум три файла: `lab.h`, `lab.cpp`, `main.cpp`.

### Первое задание

Вычислить:

```text
U = e^(x1 + y1) + e^(x2 - y2)
```

Корни `x1`, `x2` относятся к уравнению:

```text
a*x² + b*x - 1.5 = 0
```

Корни `y1`, `y2` относятся к уравнению:

```text
2*y² - y + c = 0
```

Если корни мнимые, по условию их нужно считать равными нулю. Это специальное правило задачи, а не общее математическое правило решения уравнений.

В обозначениях корней первого уравнения в методичке, по смыслу формулы, есть опечатка: вместо пары `x1, y1` следует понимать `x1, x2`.

Пользователь вводит три числа: `a`, `b`, `c`. Остальные коэффициенты уже известны из условия.

### Второе задание

Вычислить сумму:

```text
S_n = cos(1)/3 + cos(2)/7 + ... + cos(n)/(4*n - 1)
```

Пользователь вводит только целое `n` — количество слагаемых. Переменная `i` в математической записи суммы обозначает номер слагаемого, её вводить не нужно.

В текущем алгоритме рассматриваем `n >= 0`. При `n == 0` сумма пустая и равна нулю. Отрицательные значения необходимо отклонять до вычисления; в текущем коде эта проверка ещё не завершена.

## 2. Зачем три файла и как они связаны

| Файл | Содержимое | Зачем нужен |
| --- | --- | --- |
| `lab.h` | Объявления функций | Сообщает другим файлам имена функций, типы параметров и результатов |
| `lab.cpp` | Определения функций с телами | Содержит алгоритмы поиска корней и вычисления суммы |
| `main.cpp` | Функция `main()` | Получает ввод, вызывает вычисления, выводит ответы |

Слова «объявление» и «определение» отличаются:

```cpp
double recursiveSum(int n);  // Объявление: сообщает, как вызвать функцию.
```

Определение дополнительно содержит тело в фигурных скобках — что именно функция делает. Тела `findRoots` и `recursiveSum` находятся в `lab.cpp`.

Подключение `#include "lab.h"` позволяет компилятору увидеть объявления. Например, при проверке `main.cpp` компилятор узнаёт, что вызов `recursiveSum(n)` должен получить целое число и вернуть `double`.

Саму реализацию другой `.cpp` подключает через сборку:

```text
main.cpp + объявления из lab.h → объектный код main ─┐
                                                    ├→ компоновка → lab3.exe
lab.cpp  + объявления из lab.h → объектный код lab ──┘
```

У каждого `.cpp` после обработки `#include` получается своя единица трансляции. Компилятор обрабатывает их отдельно, а компоновщик связывает вызовы с определениями функций.

Поэтому при сборке нужны **оба `.cpp`**. Одного наличия `lab.cpp` в той же папке недостаточно. Писать `#include "lab.cpp"` не нужно: подключается заголовок, а реализации передаются компилятору отдельными файлами.

## 3. Построчно: `lab.h`

Текущее содержимое:

```cpp
#ifndef LAB_H
#define LAB_H

void findRoots(double a, double b, double c, double& root1, double& root2);

double recursiveSum(int n);

#endif
```

### `#ifndef LAB_H`

Это директива препроцессора: «если макрос `LAB_H` ещё не определён, обрабатывай следующий блок». Препроцессор работает до компиляции C++.

`LAB_H` — выбранное имя защитного макроса. Это не переменная, не функция и не специальное ключевое слово. Для разных заголовков выбирают разные имена таких макросов.

### `#define LAB_H`

Определяет макрос `LAB_H`. Теперь, если этот заголовок попадёт повторно в ту же единицу трансляции, проверка `#ifndef LAB_H` не пропустит его содержимое второй раз.

Это называется защитой от повторного включения — include guard.

Защита действует отдельно при обработке каждого `.cpp`. Она **не мешает** подключить `lab.h` и в `main.cpp`, и в `lab.cpp`: оба файла должны получить объявления.

У директив препроцессора в этих строках не ставится `;`.

### `void findRoots(double a, double b, double c, double& root1, double& root2);`

Это объявление функции поиска корней.

| Часть | Значение |
| --- | --- |
| `void` | Функция не возвращает значение через `return` |
| `findRoots` | Имя функции |
| `double a, double b, double c` | Три вещественных коэффициента, передаваемых по значению |
| `double& root1, double& root2` | Два выходных параметра, передаваемых по ссылке |
| `;` | Завершает объявление; тела функции здесь нет |

Функция решает общее уравнение `a*t² + b*t + c = 0`. Буква `t` здесь нужна только для пояснения: переменная уравнения может называться `x` или `y`, алгоритм от этого не меняется.

### Что означает `double&`

В объявлении параметра `double& root1` знак `&` обозначает ссылку. При вызове параметр становится другим именем для переданной переменной.

Например:

```cpp
double x1, x2;
findRoots(a, b, -1.5, x1, x2);
```

Во время этого вызова `root1` обозначает переменную `x1`, а `root2` — переменную `x2`.

```cpp
root1 = 5.0;  // В таком вызове записывает 5.0 в x1 из main().
```

Отдельного копирования результата обратно не требуется. Присваивание через ссылку меняет исходную переменную сразу.

Если убрать `&`, параметры станут локальными копиями. Изменения этих копий не запишут найденные корни в `x1` и `x2`.

Коэффициенты `a`, `b`, `c` передаются по значению: функция получает свои копии. Их достаточно, потому что коэффициенты нужно прочитать, а результаты записать в другие переменные.

`void` не означает, что функция бесполезна или ничего не вычисляет. Здесь результаты передаются через ссылки. `recursiveSum`, наоборот, передаёт единственный результат через `return`.

### `double recursiveSum(int n);`

Объявляет функцию, которая получает целое число `n` и возвращает вещественную сумму.

- `int` подходит для количества слагаемых.
- `double` нужен для результата, потому что слагаемые содержат дроби и косинусы.
- Параметр `n` передаётся по значению: у каждого рекурсивного вызова будет своя копия.

В объявлении и определении должны совпадать возвращаемый тип и типы параметров. Например, `void recursiveSum(double n)` не соответствует этому объявлению.

### `#endif`

Закрывает блок, открытый `#ifndef`. Это конец защиты заголовка, а не конец функции.

Пустые строки отделяют части файла для удобства чтения и не меняют работу программы.

## 4. Построчно: поиск корней в `lab.cpp`

Текущая первая часть файла:

```cpp
#include "lab.h"
#include <cmath>

void findRoots(double a, double b, double c, double& root1, double& root2){
    double d = b*b - 4 * a * c;
    if (a != 0){
        if ( d < 0){
            root1 = 0, root2=0;
        } else{
            root1=(-b+sqrt(d))/(2*a);
            root2=(-b-sqrt(d))/(2*a);
        }
    } else{
        root1=0;
        root2=0;
    }
}
```

### `#include "lab.h"`

Подключает объявления собственных функций. Подключение заголовка в файл реализации позволяет компилятору выявлять несогласованность объявлений и определений.

Кавычки используют для собственного заголовка; поиск обычно начинается рядом с включающим файлом.

### `#include <cmath>`

Подключает объявления математических функций стандартной библиотеки: здесь нужны `sqrt` и `cos`. Угловые скобки используют для библиотечных заголовков.

Стандартные имена этих функций — `std::sqrt`, `std::cos`, `std::exp`. Текущий компилятор принимает `sqrt` и `cos` без `std::` в этом файле, но запись с `std::` яснее указывает на стандартную библиотеку и подходит для переносимого кода.

### Строка `void findRoots(...) {`

Начинает определение функции. В отличие от объявления в заголовке здесь после списка параметров находится `{`, а не `;`.

Фигурные скобки ограничивают тело функции. Выполнение начинается с первой строки тела при каждом вызове.

### `double d = b*b - 4 * a * c;`

Объявляет локальную переменную `d` и сразу вычисляет дискриминант:

```text
D = b² - 4*a*c
```

`b*b` — умножение числа на себя. Запись `b^2` в C++ не означает возведение в квадрат: `^` — побитовое исключающее ИЛИ.

`d` существует только внутри текущего вызова `findRoots`. При следующем вызове дискриминант будет вычислен заново по новым коэффициентам.

### `if (a != 0) {`

Проверяет, что коэффициент при квадрате ненулевой. `!=` означает «не равно».

Это необходимо для формулы корней: в её знаменателе находится `2*a`, поэтому при `a == 0` она неприменима.

Оператор `=` присваивает значение, `==` сравнивает на равенство, `!=` — на неравенство.

### `if (d < 0) {`

При отрицательном дискриминанте вещественных корней нет. По условию этой работы оба результата нужно заменить нулями.

### `root1 = 0, root2=0;`

В этой строке выполняются два присваивания через ссылки: сначала `root1 = 0`, затем `root2 = 0`. Запятая здесь является оператором запятой.

Для чтения проще представить эту же строку как две:

```cpp
root1 = 0;
root2 = 0;
```

В обоих случаях переданные из `main()` переменные получат нули.

### Внутреннее `} else {`

Эта ветка относится к проверке `d < 0`. Значит, она выполняется при `d >= 0`, когда квадратный корень из дискриминанта можно вычислить в вещественных числах.

### `root1=(-b+sqrt(d))/(2*a);`

Вычисляет первый корень:

```text
root1 = (-b + √D) / (2*a)
```

`sqrt(d)` возвращает квадратный корень из `d`. Скобки вокруг `2*a` нужны, чтобы делить на весь знаменатель. Запись `/ 2 * a` означала бы сначала деление на 2, затем умножение на `a`.

### `root2=(-b-sqrt(d))/(2*a);`

Вычисляет второй корень по той же формуле, но с минусом перед квадратным корнем.

При `d == 0` оба результата совпадут. Дополнительная ветка для этого случая не обязательна.

### Внешнее `} else {` и два присваивания нулей

Эта ветка относится к `if (a != 0)`: она выполняется при `a == 0`. Текущий код записывает в оба результата нули.

Так переменные получают определённые значения, однако это **не решает уравнение**. При `a == 0` получается линейное уравнение `b*t + c = 0`. Например, `2*t - 1.5 = 0` имеет корень `0.75`, а не ноль.

Правило методички «мнимые корни считать нулём» относится к отрицательному дискриминанту квадратного уравнения и не объясняет эту ветку.

Перед сдачей нужно выбрать и реализовать поведение: отклонять `a == 0` при вводе либо отдельно обрабатывать линейное уравнение. Сейчас это ограничение программы.

### Закрывающие `}`

Скобки по очереди закрывают ветку `else` и тело функции. У `findRoots` нет возвращаемого значения, поэтому после выполнения тела управление просто возвращается к следующей строке после вызова в `main()`.

### Почему одна функция подходит двум уравнениям

| Вызов | Локальное `a` | Локальное `b` | Локальное `c` | Куда записываются результаты |
| --- | --- | --- | --- | --- |
| `findRoots(a, b, -1.5, x1, x2)` | Введённое `a` | Введённое `b` | `-1.5` | `x1`, `x2` |
| `findRoots(2, -1, c, y1, y2)` | `2.0` | `-1.0` | Введённое `c` | `y1`, `y2` |

Имена параметров функции не привязывают их к одноимённым переменным `main()`. Значения сопоставляются **по порядку аргументов**. Целые литералы `2` и `-1` автоматически преобразуются в `double` для соответствующих параметров.

Второй вызов использует тот же код, но другие значения. Изменять функцию специально для переменной `y` не нужно.

## 5. Построчно: рекурсия в `lab.cpp`

Текущая вторая часть файла:

```cpp
double recursiveSum(int n){
    if (n == 0){
        return 0;
    }
    if (n >= 0){
        return recursiveSum(n-1) + cos(n)/(4.0*n - 1.0);
    }
}
```

### Откуда берётся рекурсивная формула

Выделяем последнее слагаемое из суммы:

```text
S_n = [cos(1)/3 + ... + cos(n-1)/(4*(n-1)-1)] + cos(n)/(4*n-1)
```

Выражение в квадратных скобках — это та же задача, но для `n - 1` слагаемых:

```text
S_0 = 0
S_n = S_(n-1) + cos(n)/(4*n-1), если n > 0
```

Рекурсивный вызов вычисляет предыдущую сумму, текущий вызов добавляет к ней последнее слагаемое.

### `double recursiveSum(int n) {`

Начинает определение функции, которая возвращает всю сумму от первого до `n`-го слагаемого включительно.

Каждый вызов получает собственную копию `n`. Вызов `recursiveSum(n - 1)` не уменьшает `n` в уже работающем вызове: он передаёт меньшее значение в новый вызов.

### `if (n == 0) {`

Проверяет базовый случай. Для пустой суммы ответ известен без новых вызовов.

База нужна, чтобы рекурсия остановилась. При положительном `n` последовательное уменьшение на единицу обязательно доведёт аргумент до нуля.

### `return 0;`

Завершает текущий вызов и возвращает ноль вызывающему коду. Из-за типа результата `double` целый литерал `0` преобразуется в `0.0`.

`return` завершает текущую функцию, а не всю программу. Вызвавшая её функция продолжает вычисление со своим значением `n`.

После этого `return` остальные строки текущего вызова уже не выполняются.

### `if (n >= 0) {`

После обработки `n == 0` эта ветка фактически выполняется только при `n > 0`.

Но наличие проверки ещё не означает, что отрицательный ввод корректно обработан. При `n < 0` оба условия ложны и выполнение доходит до конца функции **без возвращаемого значения**. Для этой функции при таком вызове получается неопределённое поведение.

Компилятор предупреждает:

```text
warning: control reaches end of non-void function [-Wreturn-type]
```

Нужно отклонять отрицательные значения до вызова и продумать поведение самой функции для недопустимого аргумента. Простое добавление условия без ветки обработки ошибку не устраняет. Нельзя считать, что при отсутствии `return` автоматически возвращается ноль.

### `return recursiveSum(n-1) + cos(n)/(4.0*n - 1.0);`

Это рекурсивный шаг. Разбери его по частям:

| Выражение | Что означает |
| --- | --- |
| `recursiveSum(n-1)` | Сумма первых `n - 1` слагаемых |
| `cos(n)` | Косинус номера текущего слагаемого |
| `4.0*n - 1.0` | Знаменатель текущего слагаемого |
| `cos(n)/(4.0*n - 1.0)` | Слагаемое с номером `n` |
| `+` | Добавление последнего слагаемого к предыдущей сумме |
| `return` | Передача всей полученной суммы вызывающему коду |

`cos` принимает угол в радианах. В этой задаче передаётся само число `n`: перевода из градусов не требуется.

Литералы `4.0` и `1.0` имеют тип `double`, поэтому знаменатель вычисляется с плавающей точкой. Здесь `cos(n)` и так возвращает `double`, но такая запись также позволяет избежать целочисленного вычисления произведения `4*n`.

Если оставить только `return recursiveSum(n - 1);`, все вызовы передадут обратно ноль из базы: ни одно слагаемое не будет добавлено.

### Как вычисляется `recursiveSum(3)`

Сначала возникают вложенные вызовы:

```text
recursiveSum(3) ждёт результат recursiveSum(2)
  recursiveSum(2) ждёт результат recursiveSum(1)
    recursiveSum(1) ждёт результат recursiveSum(0)
      recursiveSum(0) возвращает 0
```

Затем возвращаются результаты:

```text
recursiveSum(1) = 0           + cos(1)/3  ≈ 0.1801007686
recursiveSum(2) = 0.1801007686 + cos(2)/7  ≈ 0.1206512205
recursiveSum(3) = 0.1206512205 + cos(3)/11 ≈ 0.0306519027
```

У вызова для `n == 3` его локальное `n` остаётся равным 3, пока вложенные вызовы считают свои суммы. Благодаря этому при возвращении он добавляет именно `cos(3)/11`.

Стек вызовов хранит сведения, необходимые для продолжения каждого вызова. Для этого алгоритма выполняется `n + 1` вызовов, включая базовый. Время и дополнительная память растут пропорционально `n`: `O(n)`.

Для очень большого `n` глубина вложенности может превысить доступный размер стека. Допустимый предел зависит от среды и сборки; для учебных проверок используй небольшие значения.

## 6. Построчно: `main.cpp`

Текущий код:

```cpp
#include "lab.h"
#include <iostream>
#include <cmath>

using namespace std;

int main(){
    double a, b, c, x1, x2, y1, y2, U;
    cin >> a;
    cin >> b;
    cin >> c;
    findRoots(a, b, -1.5, x1, x2);
    findRoots(2, -1, c, y1, y2);
    U = exp(x1+y1)+exp(x2-y2);
    cout << U << "\n";

    //--------------------------
    int n;
    cin >> n;
    double S = recursiveSum(n);
    cout << S;
}
```

### Подключения и пространство имён

- `#include "lab.h"` делает видимыми объявления `findRoots` и `recursiveSum`.
- `#include <iostream>` нужен для `std::cin` и `std::cout`.
- `#include <cmath>` нужен здесь для `std::exp`. Подключение `<cmath>` в `lab.cpp` не подключает его автоматически в другой `.cpp`.
- `using namespace std;` разрешает использовать имена из `std` без префикса, поэтому ниже написано `cin`, `cout`, `exp`. Эта строка не подключает библиотеки и не действует внутри отдельно компилируемого `lab.cpp`.

### `int main() {`

Определяет основную функцию программы. В обычной консольной программе пользовательский код начинает выполняться здесь.

`int` — тип кода завершения. Достижение закрывающей скобки `main()` эквивалентно `return 0;`, то есть успешному завершению. Это особое правило `main()`: оно не разрешает пропускать `return` в `recursiveSum`.

### `double a, b, c, x1, x2, y1, y2, U;`

Объявляет вещественные переменные:

| Переменные | Назначение |
| --- | --- |
| `a`, `b`, `c` | Вводимые коэффициенты |
| `x1`, `x2` | Корни первого уравнения |
| `y1`, `y2` | Корни второго уравнения |
| `U` | Ответ первого задания |

В этой строке начальные значения не заданы. Такие локальные переменные нельзя читать до присваивания. Коэффициенты должны получить значения при успешном вводе, корни — в `findRoots`, `U` — при вычислении выражения.

Передавать `x1` и `x2` по ссылке допустимо: функция записывает в них результаты, не читая прежних значений.

### Три строки `cin >> ...;`

Считывают `a`, затем `b`, затем `c`. Ввод можно разделять пробелами или переводами строк. Для дробных значений в приведённых примерах используется точка.

Сейчас успешность чтения не проверяется. Перед вычислением нужно убедиться, что числа действительно прочитаны; буква вместо числа приводит к ошибке потока. Пока состояние ошибки не обработано, последующие операции ввода тоже не смогут нормально читать данные.

### `findRoots(a, b, -1.5, x1, x2);`

Первый вызов решает `a*x² + b*x - 1.5 = 0` и записывает результаты в `x1`, `x2`.

### `findRoots(2, -1, c, y1, y2);`

Второй вызов решает `2*y² - y + c = 0` и записывает результаты в `y1`, `y2`.

Второй вызов не перезаписывает `x1` и `x2`, потому что в качестве выходных параметров переданы другие переменные.

### `U = exp(x1+y1)+exp(x2-y2);`

Вычисляет результат первого задания. Функция `exp(t)` возвращает `e` в степени `t`. Во второй экспоненте нужен именно `x2 - y2`.

`^` для возведения в степень здесь использовать нельзя.

### `cout << U << "\n";`

Выводит `U`, затем перевод строки. В строковом литерале `\n` означает переход на следующую строку.

### `//--------------------------`

Комментарий, визуально отделяющий задания. На вычисления не влияет.

### `int n;` и `cin >> n;`

Объявляют целое количество слагаемых и считывают его. До вызова функции нужно проверить успешность ввода и допустимый диапазон.

### `double S = recursiveSum(n);`

Вызывает рекурсивную функцию, получает её итоговый результат и записывает его в `S`.

Здесь не нужен цикл и не нужно начинать `S` с единицы. Все слагаемые уже учитываются внутри функции.

### `cout << S;`

Выводит ответ второго задания. Перевода строки после него сейчас нет; можно добавить `<< "\n"` для удобства.

### Последняя `}`

Заканчивает `main()`. Пустые строки после неё ничего не делают.

## 7. Сборка и запуск в PowerShell

### 7.1. Что установить на ноутбуке один раз

Эти инструкции рассчитаны на ноутбук с Windows x64. Здесь используется GCC из MSYS2, окружение **UCRT64**, установленное в `C:\msys64`. Для такой же схемы сборки на ноутбуке нужны компилятор и его библиотеки; один VS Code их не устанавливает.

1. Установи [MSYS2 с официального сайта](https://www.msys2.org/) в `C:\msys64`. Если выберешь другую папку, замени путь во всех командах ниже.
2. Открой **MSYS2 UCRT64** через меню «Пуск» и выполни команду установки компилятора:

   ```bash
   pacman -S --needed mingw-w64-ucrt-x86_64-gcc
   ```

   Если появится запрос подтверждения установки, введи `Y` и нажми Enter. Эта команда предназначена для терминала MSYS2, а не обычного PowerShell. Порядок установки GCC описан в [инструкции MSYS2](https://www.msys2.org/).

3. Открой папку репозитория в VS Code. Для подсказок и подсветки ошибок установи расширение **C/C++ от Microsoft**; саму сборку выполняет установленный GCC. Настройка этого сочетания описана в [документации VS Code](https://code.visualstudio.com/docs/cpp/config-mingw).

Версии GCC на двух компьютерах могут различаться. Для этой лабораторной нужны поддержка C++17 и одинаково выбранное окружение UCRT64, а не точное совпадение номера версии.

### 7.2. Строка для терминала PowerShell

В VS Code выбери **Terminal → New Terminal** и убедись, что открыт PowerShell. Если компилятор установлен в указанную папку, выполни:

```powershell
$env:Path = "C:\msys64\ucrt64\bin;" + $env:Path
```

Это строка, которая позволяет текущему терминалу находить компилятор и необходимые для запуска DLL. Она работает и на этом компьютере, и на ноутбуке **при наличии установленного GCC по этому пути**. Она не скачивает и не устанавливает компилятор.

Проверь настройку:

```powershell
Test-Path 'C:\msys64\ucrt64\bin\g++.exe'
g++ --version
```

Первая команда должна вывести `True`, вторая — информацию о версии GCC. Если первая выдаёт `False`, проверь установку и путь: изменение `PATH` не создаёт отсутствующий `g++.exe`.

После закрытия терминала изменение его `PATH` пропадёт. Можно повторять строку при каждом запуске либо один раз добавить `C:\msys64\ucrt64\bin` в пользовательский `Path` через настройки переменных среды Windows. После постоянного изменения полностью закрой и заново открой VS Code и терминалы, чтобы они получили новое окружение. Этот способ также приведён в [инструкции VS Code по настройке PATH](https://code.visualstudio.com/docs/cpp/config-mingw#_installing-the-mingw-w64-toolchain).

### 7.3. Как собрать лабораторную

Если терминал открыт в корне репозитория, перейди в папку лабораторной:

```powershell
Set-Location .\sem5\C_plus_plus\lab_3
```

Если уже находишься в `lab_3`, переходить повторно не нужно.

После настройки из предыдущего пункта собери оба `.cpp`. Полный блок для PowerShell из папки `lab_3`:

```powershell
$env:Path = "C:\msys64\ucrt64\bin;" + $env:Path
& 'C:\msys64\ucrt64\bin\g++.exe' -std=c++17 -Wall -Wextra -pedantic main.cpp lab.cpp -o lab3.exe
if ($LASTEXITCODE -eq 0) { .\lab3.exe }
```

Разбор команды:

| Часть | Значение |
| --- | --- |
| `$env:Path = ...` | Добавляет папку с компилятором и его DLL в пути поиска этого терминала |
| `&` | Оператор PowerShell для запуска команды, путь которой записан строкой |
| `g++.exe` | Компилятор C++ |
| `-std=c++17` | Выбор стандарта C++17 |
| `-Wall -Wextra -pedantic` | Дополнительные предупреждения и проверки |
| `main.cpp lab.cpp` | Два исходных файла одной программы |
| `-o lab3.exe` | Имя выходного исполняемого файла |
| `if ($LASTEXITCODE -eq 0)` | Запускает программу только при успешном завершении компилятора |
| `.\lab3.exe` | Запуск программы из текущей папки |

Заголовок `lab.h` отдельно в список исходных файлов не добавляется: его содержимое получают через `#include`.

Если собрать только `main.cpp`, компоновщик не найдёт определения функций из `lab.cpp`. Типичное сообщение — `undefined reference`.

Локальный скрипт `.vscode/build-cpp.ps1`, используемый на этом компьютере, передаёт компилятору только активный исходный файл. Он не входит в состав этой лабораторной, и на ноутбуке его может не быть. Для этой работы используй приведённую команду с обоими `.cpp` либо отдельно настрой многофайловую сборку.

Если Windows пишет, что не найдена `libstdc++-6.dll`, это проблема поиска библиотеки при запуске. Она находится в `C:\msys64\ucrt64\bin`; приведённая строка с `PATH` помогает при запуске из того же терминала. Она не изменяет системные настройки и не исправляет запуск двойным щелчком в Проводнике.

После изменения кода нужно заново собрать программу. Уже существующий `lab3.exe` сам не обновляется. Если сборка завершилась ошибкой, старый `.exe` может остаться на месте — его запуск не проверяет исправленный код.

### 7.4. Что делать после запуска

Исходные файлы `.cpp` сами по себе не запускаются: сначала компилятор создаёт `lab3.exe`, затем Windows выполняет этот файл. Пока код не менялся, повторно компилировать его перед каждым запуском не требуется.

Для отдельного запуска уже собранной программы из папки `lab_3` введи в том же настроенном PowerShell:

```powershell
.\lab3.exe
```

В текущем коде нет текстовых приглашений ко вводу. Если после запуска экран ничего не показывает, программа ждёт `cin`, это нормально.

Пройди пример вручную:

1. Введи `1` и нажми Enter — это коэффициент `a`.
2. Введи `0` и нажми Enter — коэффициент `b`.
3. Введи `0` и нажми Enter — коэффициент `c`.
4. Программа выведет `5.90492` — результат `U` — и будет ждать следующий ввод.
5. Введи `3` и нажми Enter — количество слагаемых `n`.
6. Программа выведет `0.0306519` — результат `S` — и завершится.

Запускай программу именно в терминале: там можно вводить значения для `cin`. Во время ожидания ввода её можно прервать сочетанием **Ctrl+C**.

Для быстрой проверки того же примера можно заранее передать все четыре числа через стандартный ввод:

```powershell
'1 0 0 3' | .\lab3.exe
```

Знак `|` передаёт строку слева на вход программе справа. Здесь `cin` прочитает числа из этой строки вместо ручного набора. Порядок чисел остаётся тем же: `a b c n`.

При переносе на ноутбук получи исходники из Git и собери `.exe` там. Сам `lab3.exe` исключён из Git правилом `*.exe`; установленный MSYS2 тоже не переносится вместе с репозиторием.

## 8. Контрольные примеры

Порядок ввода: `a`, `b`, `c`, затем `n`. Программа сначала ждёт три коэффициента, выводит `U`, затем ждёт `n` и выводит сумму.

Например, можно ввести одной строкой:

```text
1 0 0 3
```

Ожидаемый вывод с текущей точностью:

```text
5.90492
0.0306519
```

Проверка первого ответа вручную:

```text
x² - 1.5 = 0 → x1 = √1.5, x2 = -√1.5
2*y² - y = 0 → y1 = 0.5, y2 = 0
U = exp(√1.5 + 0.5) + exp(-√1.5) ≈ 5.9049219535
```

Ещё примеры для самостоятельной проверки:

| Ввод `a b c n` | Ожидаемое `U` | Ожидаемое `S` | Что проверяется |
| --- | --- | --- | --- |
| `1 0 0 1` | `5.90492` | `0.180101` | Одно слагаемое |
| `1 0 0 0` | `5.90492` | `0` | База рекурсии |
| `-1 0 1 1` | `2` | `0.180101` | Оба дискриминанта отрицательны |
| `-1.5 3 0.125 3` | `5.60734` | `0.0306519` | Оба дискриминанта равны нулю |

При отрицательных дискриминантах все четыре корня заменяются нулями, поэтому `U = exp(0) + exp(0) = 2`.

При нулевых дискриминантах в последнем примере `x1 = x2 = 1`, `y1 = y2 = 0.25`.

По умолчанию `cout` выводит ограниченное количество значащих цифр, поэтому ответ может быть округлён. Это само по себе не означает ошибку вычисления.

При подготовке README текущая версия собрана с предупреждениями и запущена на примерах `1 0 0 3` и `-1 0 1 1`: результаты совпали с ожидаемыми. Компилятор выдал предупреждение об отсутствии `return` для отрицательного `n`.

## 9. Что ещё исправить в текущем коде

Эта часть нужна, чтобы отличать объяснение существующей реализации от утверждения, что все случаи уже обработаны.

1. **Отрицательное `n`.** Сейчас `recursiveSum` может закончиться без `return`. Нужно определить обработку недопустимого аргумента и не вызывать вычисление с отрицательным количеством слагаемых.
2. **Нулевое `a`.** Присваивание нулей предотвращает чтение незаданных корней, но не даёт правильного решения линейного уравнения. Нужна проверка ввода или отдельная обработка.
3. **Ошибка чтения.** Проверять успешность `cin` для коэффициентов и `n`, прежде чем использовать переменные.
4. **Слишком большое `n`.** Для рекурсии нужна разумная граница ввода, поскольку стек конечен.

Для удобства можно также подписать запросы ввода и результаты, добавить перевод строки после `S`, использовать `std::sqrt` и `std::cos` в `lab.cpp` и единообразно расставить пробелы. Это улучшения читаемости; они не заменяют исправление перечисленных случаев.

## 10. Как восстановить код самостоятельно

В методичке требуется уметь объяснить программу без комментариев и восстановить удалённый участок до 20 строк. Тренируйся восстанавливать ход решения, а не только последовательность символов.

### Восстановление `lab.h`

1. Открыть защиту `#ifndef LAB_H` и определить макрос.
2. Объявить функцию корней: три входных `double`, два выходных `double&`, результат `void`.
3. Объявить функцию суммы: параметр `int`, результат `double`.
4. Закрыть защиту `#endif`.

### Восстановление поиска корней

1. Вспомнить общее уравнение `a*t² + b*t + c = 0`.
2. Проверить, применима ли квадратная формула: `a != 0`.
3. Вычислить `D = b*b - 4*a*c`.
4. При `D < 0` записать два нуля по правилу задания.
5. При `D >= 0` записать формулы с плюсом и минусом перед `sqrt(D)`.
6. Не забыть скобки вокруг числителя и знаменателя.
7. Отдельно объяснить выбранное поведение при `a == 0`.

### Восстановление рекурсии

1. Сказать словами, что возвращает функция: сумму первых `n` слагаемых.
2. Назвать базу: сумма нуля слагаемых равна нулю.
3. Выделить последнее слагаемое: `cos(n)/(4*n - 1)`.
4. Записать предыдущую сумму через вызов для `n - 1`.
5. Сложить предыдущую сумму с последним слагаемым и вернуть результат.
6. Проверить допустимость входных значений и наличие определённого поведения на всех путях.

### Восстановление `main()`

1. Подключить объявления функций, ввод-вывод и математику.
2. Прочитать и проверить коэффициенты.
3. Дважды вызвать одну функцию корней с разными коэффициентами и выходными переменными.
4. Вычислить `U` и вывести результат.
5. Прочитать и проверить `n`.
6. Вызвать рекурсивную функцию и вывести сумму.

## 11. Вопросы для самопроверки

Сначала ответь своими словами, затем сверяйся с пояснением.

1. **Почему `void findRoots` всё-таки выдаёт результаты?** Потому что записывает их в переданные по ссылке переменные `root1`, `root2`.
2. **Что изменится, если убрать `&`?** Функция начнёт менять копии выходных параметров; переменные в `main()` не получат корни.
3. **Почему нельзя просто написать `return root1, root2;`?** Оператор запятой не возвращает два результата: значением выражения будет правый операнд. Кроме того, текущая функция объявлена как `void`.
4. **Почему `lab.h` нужен обоим `.cpp`?** Вызывающий файл получает объявления, а файл реализации согласует с ними определения.
5. **Почему защита заголовка не мешает второму `.cpp`?** Каждый `.cpp` обрабатывается отдельно, со своим состоянием препроцессора.
6. **Почему одной команды сборки только `main.cpp` недостаточно?** Объявления есть, а объектного кода определений функций из `lab.cpp` нет.
7. **Почему `#include <cmath>` есть в двух файлах?** Каждый `.cpp` должен видеть объявления библиотечных функций, которые сам использует.
8. **Почему во втором вызове корней переданы `2, -1, c`?** Это коэффициенты при `y²`, `y` и свободный член второго уравнения.
9. **Почему при отрицательном `D` результаты нулевые?** Так требует условие лабораторной.
10. **Почему при `a == 0` нельзя применять квадратную формулу?** Уравнение перестаёт быть квадратным, а знаменатель `2*a` становится нулём.
11. **Где остановится рекурсия для `n = 3`?** На вызове с аргументом 0.
12. **Почему вызов для 3 не забывает свою тройку?** У каждого вызова собственный параметр; сведения для продолжения сохраняются в стеке вызовов.
13. **Почему в рекурсивной формуле нет `i`?** Текущий параметр `n` одновременно задаёт размер подзадачи и номер её последнего слагаемого.
14. **Почему не нужно дополнительно прибавлять единицу к `S`?** База равна нулю, а все слагаемые уже добавляются рекурсивными вызовами.
15. **Чем `return` в `recursiveSum` отличается от вывода `cout`?** `return` передаёт число вызывающему коду, `cout` выводит представление числа в поток.
16. **Почему нельзя утверждать, что отрицательное `n` уже обработано условием `if (n >= 0)`?** При ложном условии функция доходит до конца без результата; ветки корректной обработки ошибки пока нет.
17. **Почему отсутствие `return 0;` в `main()` допустимо, а отсутствие результата в `recursiveSum` — нет?** Для достижения конца `main()` есть специальное правило языка; обычная функция с результатом `double` такого правила не имеет.
