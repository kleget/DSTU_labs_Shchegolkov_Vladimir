# Работа с файлами в C++ с нуля

Этот файл объясняет конструкции из [main.cpp](main.cpp). Условия варианта и инструкция запуска находятся в [README.md](README.md).

## 1. Зачем нужен файл и что такое поток

Переменная существует в памяти работающей программы. После завершения программы её значение теряется. Файл хранится на диске: программа может записать в него данные и прочитать их при следующем запуске.

Поток — объект, через который программа получает или отправляет данные. С потоками ты уже работал:

```cpp
cin >> number;
cout << number;
```

`cin` получает данные, обычно с клавиатуры, `cout` отправляет их на экран. Файловый поток работает похожим образом, но связан с файлом.

| Объект или класс | Для чего нужен | Заголовок |
| --- | --- | --- |
| `cin` | Ввод из стандартного потока | `<iostream>` |
| `cout` | Обычный вывод | `<iostream>` |
| `cerr` | Вывод сообщений об ошибках | `<iostream>` |
| `ifstream` | Чтение из файла | `<fstream>` |
| `ofstream` | Запись в файл | `<fstream>` |
| `fstream` | Чтение и запись через один объект | `<fstream>` |

`ifstream` и `ofstream` — классы. В строке `ifstream input("text.txt");` переменная `input` является объектом класса `ifstream`.

В программе есть `using namespace std;`, поэтому стандартные имена написаны без `std::`. Например, `ifstream` здесь означает `std::ifstream`.

## 2. Открытие, запись и закрытие

Простейшая запись:

```cpp
ofstream output("result.txt");
output << "Привет!" << '\n';
output << 42 << '\n';
output.close();
```

Сначала создаётся поток и открывается файл. Затем `<<` отправляет в него данные. Наконец, `close()` закрывает файл и завершает вывод накопленных данных.

**Обычный `ofstream` очищает существующий файл при открытии.** Если файла нет, он пытается создать его. `ifstream` открывает существующий файл для чтения и не создаёт отсутствующий.

После открытия нужна проверка:

```cpp
ifstream input("text.txt");
if (!input.is_open()) {
    throw runtime_error("Не удалось открыть text.txt.");
}
```

`is_open()` отвечает, связан ли поток с открытым файлом. Знак `!` означает отрицание. Открытие может не удаться, если файла нет, указан неверный путь или нет доступа.

В записи `input("text.txt")` имя файла — строка `"text.txt"`, а `input` — имя переменной-потока. Они не обязаны совпадать.

Относительный путь отсчитывается от **текущей рабочей папки запущенной программы**, а не от места, где лежит `.cpp`. Поэтому скрипт запуска сначала переходит в `lab_4`.

### Режимы открытия

| Режим | Значение |
| --- | --- |
| `ios::in` | Читать; используется по умолчанию у `ifstream` |
| `ios::out` | Писать; используется по умолчанию у `ofstream` |
| `ios::trunc` | Очистить существующее содержимое |
| `ios::app` | Каждую запись добавлять в конец |
| `ios::ate` | При открытии сразу перейти в конец; затем можно перемещаться |
| `ios::binary` | Работать без преобразований текстового режима |

Например, дописывание текста:

```cpp
ofstream output("result.txt", ios::app);
output << "Ещё одна строка\n";
```

Режимы объединяются знаком `|`:

```cpp
ifstream file("vouchers.txt", ios::binary | ios::ate);
```

Это открытие для чтения в бинарном режиме с начальной позицией в конце. `ate` нужен в `load`, чтобы сразу узнать размер файла через `tellg()`.

Файловый поток также закрывается автоматически, когда объект прекращает существовать, например при выходе из метода. В коде явно вызывается `close()` после записи, чтобы затем проверить, успешно ли завершён вывод.

## 3. Как читать текст

### Чтение отдельных значений: `>>`

Для файла с числами:

```text
10 20
30
```

можно написать:

```cpp
int number;
while (input >> number) {
    cout << number << '\n';
}
```

`>>` пропускает начальные пробельные символы и пытается прочитать значение нужного типа. Если читать `string`, получится одно слово до пробельного символа. Поэтому для текста с пробелами и пустыми строками этот способ не подходит.

### Чтение строки: `getline`

```cpp
string line;
while (getline(input, line)) {
    cout << line << '\n';
}
```

`getline` читает строку целиком, включая пробелы внутри. Перевод строки извлекается из потока, но в переменную `line` не записывается. Для пустой строки чтение успешно, а `line` становится пустой строкой.

Именно поэтому в задании 1 при записи строки обратно нужен `output << line << '\n';`.

### Чтение символа: `get`

```cpp
char ch;
while (input.get(ch)) {
    output << ch;
}
```

`get` читает очередной `char`, сохраняя пробелы, табуляции и переводы строк. Для `char` это один байт; связь с буквами UTF-8 разобрана дальше.

Метод `peek()` смотрит следующий байт **без его извлечения**. Следующий `get` прочитает именно его. Если данных больше нет, `peek()` возвращает специальное значение конца файла, которое не попадает в диапазон 128–191.

### Почему не `while (!input.eof())`

`eof()` сообщает, что конец уже обнаружен при чтении. До попытки прочитать за последними данными этого флага может ещё не быть. Поэтому проверять конец до чтения ненадёжно: можно повторно обработать старое значение.

Условия `while (getline(input, line))` и `while (input.get(ch))` проверяют результат самого чтения. Тело выполняется только после успешного получения данных.

В `copyLastLines` после первого прохода:

```cpp
input.clear();
input.seekg(0);
```

`clear()` сбрасывает флаги состояния потока, возникшие при достижении конца. Он **не очищает содержимое файла**. `seekg(0)` возвращает позицию чтения к началу. После этого файл можно читать второй раз.

## 4. Символы, строки и UTF-8

`char` хранит один байт. `string` хранит последовательность таких байтов. Латинская буква в UTF-8 занимает один байт, русская обычно два, некоторые символы — три или четыре. Поэтому два разных понятия: количество байтов и количество видимых букв.

В задании 2 байты одного символа собираются в `symbol`:

```cpp
string symbol(1, ch);
while (input.peek() >= 128 && input.peek() <= 191) {
    input.get(ch);
    symbol += ch;
}
```

`string symbol(1, ch)` создаёт строку из одного экземпляра `ch`. Для корректного UTF-8 байты продолжения многобайтового символа находятся в диапазоне 128–191. Цикл присоединяет их к первому байту. Например, два байта буквы `я` обрабатываются как одна строка-символ.

Затем:

```cpp
if (seen.find(symbol) == string::npos) {
    seen += symbol;
    output << symbol;
}
```

`find` ищет подстроку и возвращает позицию её начала. `string::npos` — специальное значение «не найдено». Если символ ещё не встречался, он добавляется в `seen` и выводится. Все добавленные подстроки — полные символы UTF-8, поэтому поиск корректен для выбранной кодировки.

Важен порядок действий: сначала проверить отсутствие, затем добавить. После добавления следующая такая же буква будет найдена и пропущена.

В Windows вызовы `SetConsoleCP(CP_UTF8)` и `SetConsoleOutputCP(CP_UTF8)` настраивают консоль на ввод и вывод UTF-8. Блок `#ifdef _WIN32` включает эти вызовы только при сборке для Windows. Исходный текстовый файл также сохраняй в UTF-8.

В текстовом режиме Windows пара байтов `\r\n`, обозначающая конец строки, читается как `\n`. Поэтому обычный перевод строки считается одним символом. Это стандартное поведение текстового потока.

## 5. Текстовый и бинарный файл

На диске оба состоят из байтов. Отличается способ, которым программа их записывает и понимает.

При текстовой записи числа `123` через `<<` в файл попадают символы `1`, `2`, `3`. Их удобно читать человеку. При бинарной записи `int` сохраняются байты его представления в памяти. Они не обязаны выглядеть как печатные символы.

`ios::binary` выбирает бинарный режим, а методы `write` и `read` передают нужное количество байтов. Одного `ios::binary` недостаточно, чтобы `<< 123` стал записью внутреннего представления числа: `<<` продолжает форматировать число в текст.

Расширение имени тоже не меняет способ записи. В этой лабораторной `vouchers.txt` — бинарный файл с расширением `.txt` по требованию методички.

### Почему в структуре массивы `char`, а не `string`

```cpp
struct Voucher {
    char fullName[100];
    // Остальные поля смотри в main.cpp.
};
```

Массив `char[100]` содержит сам текст внутри структуры. Строка заканчивается нулевым символом `\0`; поэтому для текста доступно не более 99 байтов.

`string` устроен сложнее: может хранить указатель на память с текстом. Запись байтов самого объекта `string` не сохраняет содержимое этой памяти. Чтобы читать и писать всю структуру целиком самым простым способом, здесь используются поля фиксированного размера.

`readField` сначала проверяет длину введённой строки и только затем вызывает `strcpy(field, line.c_str())`. `c_str()` предоставляет текст в виде строки с завершающим нулём. `strcpy` копирует её вместе с этим нулём в проверенный по размеру массив.

`Voucher voucher{};` при вводе новой записи первоначально заполняет поля нулями, а затем программа записывает введённые значения.

### Запись и чтение структуры

```cpp
file.write(reinterpret_cast<const char*>(&data[i]), sizeof(Voucher));
```

Разбор:

| Часть | Значение |
| --- | --- |
| `data[i]` | Одна структура из массива |
| `&data[i]` | Адрес этой структуры в памяти |
| `reinterpret_cast<const char*>(...)` | Позволяет передать этот адрес как адрес последовательности байтов для чтения из памяти |
| `sizeof(Voucher)` | Полный размер одной структуры в байтах |
| `write(адрес, размер)` | Копирует указанное число байтов из памяти в файл |

`const` здесь означает, что `write` не меняет исходные байты структуры.

Обратная операция:

```cpp
file.read(reinterpret_cast<char*>(&voucher), sizeof(Voucher));
```

`read` копирует байты из файла в память структуры. Здесь `const` нет, потому что содержимое переменной должно измениться.

Сохранённый таким способом файл рассчитан на чтение программой с тем же устройством структуры. Компилятор может добавлять промежутки между полями, поэтому размер всегда берётся через `sizeof`, а не вычисляется вручную. Для этой лабораторной сохраняй и загружай файл своей программой.

## 6. Позиция в файле и чтение отдельной записи

Поток помнит, откуда будет читать дальше. После чтения позиция сдвигается вперёд. Два метода позволяют её узнать и изменить:

```cpp
streamoff size = file.tellg();
file.seekg(0);
```

`tellg()` возвращает текущую позицию чтения. Для бинарного файла, открытого с `ios::ate`, это размер файла в байтах. `seekg(0)` перемещает чтение в начало. `streamoff` — целочисленный тип для файловых смещений.

В файле путёвок структуры идут подряд, без заголовка:

```text
[запись 1][запись 2][запись 3]...
```

Количество записей равно:

```text
размер файла / sizeof(Voucher)
```

Перед делением `load` проверяет, что размер неотрицательный и делится на размер структуры без остатка. Ненулевой остаток означает, что последняя запись неполная либо файл не соответствует этому формату. Пустой файл содержит ноль записей.

Начало записи с порядковым номером `number`:

```cpp
file.seekg((number - 1) * recordSize);
```

Первая запись начинается с байта 0, вторая — с байта `recordSize`, третья — с байта `2 * recordSize`. Вычитается единица, потому что пользователь нумерует записи с 1, а смещение начинается с 0.

После перехода `readOne` выполняет один `read`. Поэтому весь файл в память не загружается. Если нужной полной записи нет, чтение не удаётся и возникает исключение.

Для потока записи существуют похожие методы `tellp()` и `seekp()`. Буква `g` относится к чтению (get), `p` — к записи (put).

## 7. Структура, класс и динамический массив

`Voucher` описывает одну путёвку: набор связанных полей. `VoucherList` управляет несколькими такими структурами и операциями над ними.

У класса поля до `public:` закрытые: обращаться к ним напрямую из `main` нельзя. Публичные методы позволяют добавлять, удалять, сохранять и искать записи. Например, `vouchers.add(voucher)` вызывает метод `add` у объекта `vouchers`.

```cpp
Voucher* data;
int count;
```

Звёздочка в `Voucher*` означает указатель: переменная хранит адрес области памяти с элементами типа `Voucher`. `count` — число используемых элементов. Индексация `data[i]` работает как у обычного массива.

### Создание и освобождение памяти

```cpp
VoucherList() : data(nullptr), count(0) {}
```

Это конструктор: он вызывается при создании объекта. Часть после `:` задаёт начальные значения полей. `nullptr` означает, что указатель пока ни на какой массив не указывает; записей первоначально ноль.

```cpp
Voucher* next = new Voucher[count + 1];
```

`new[]` выделяет массив во время выполнения программы. Его размер может зависеть от текущего количества записей. В этом смысл динамического массива.

В `add` сначала создаётся увеличенный массив, старые записи копируются циклом, а новая записывается в `next[count]`. Затем:

```cpp
delete[] data;
data = next;
count++;
```

`delete[]` освобождает прежний массив. Присваивание меняет адрес, хранящийся в `data`: теперь он указывает на новый массив. После увеличения `count` новая запись тоже входит в используемую часть.

При удалении, например, второй записи из трёх третья копируется на место второй, затем `count` уменьшается. Старая последняя ячейка остаётся выделенной, но больше не выводится и не сохраняется.

```cpp
~VoucherList() {
    delete[] data;
}
```

Это деструктор: вызывается при уничтожении объекта и освобождает оставшийся массив. Память, полученную через `new[]`, освобождают через `delete[]`.

В `load` сначала читается новый массив. Старый освобождается только после успешного чтения: так ошибка чтения не оставляет объект с частично загруженными данными.

### Ещё несколько обозначений из методов

`const Voucher& voucher` — параметр-ссылка на существующую структуру. `&` в объявлении параметра обозначает ссылку, а `const` запрещает менять структуру через этот параметр. Например, `printVoucher` может читать поля, но не исправлять их.

`const` после списка параметров метода, как в `int getCount() const`, означает, что метод не меняет поля объекта. Он просто возвращает число записей.

`static_cast<int>(...)` явно преобразует значение к `int`. В `load` это нужно для количества записей; перед преобразованием проверяется, что оно не больше `INT_MAX` — максимального значения `int`.

## 8. Ошибки и исключения

Поток хранит сведения об успехе операций:

| Проверка | Что означает |
| --- | --- |
| `file.is_open()` | Файл открыт |
| `if (file)` | Нет состояния ошибки, мешающего операции |
| `if (!file)` | Поток находится в состоянии ошибки |
| `file.eof()` | При чтении обнаружен конец файла |
| `file.bad()` | Произошла серьёзная ошибка ввода-вывода |
| `file.clear()` | Сбросить флаги состояния |

Само по себе обычное неудачное открытие потока не выбрасывает исключение. В нашей программе это делается явно:

```cpp
if (!file.is_open()) {
    throw runtime_error("Файл не существует или недоступен.");
}
```

`throw` прерывает обычное выполнение и передаёт объект ошибки ближайшему подходящему `catch`. `runtime_error` — стандартный тип исключения с текстовым сообщением из заголовка `<stdexcept>`.

В `main` основная работа помещена в `try`:

```cpp
try {
    // Вызов методов программы.
} catch (const exception& error) {
    cerr << "Ошибка: " << error.what() << '\n';
    return 1;
}
```

`runtime_error` является разновидностью `exception`, поэтому этот `catch` его получает. `what()` возвращает текст сообщения. `cerr` отправляет его в поток ошибок. `return 1` завершает программу с кодом ошибки; обычный выход использует `return 0`.

Когда исключение покидает метод, его локальные файловые потоки уничтожаются и закрывают файлы. Когда оно покидает область объекта `vouchers`, деструктор освобождает его массив.

Конец текстового файла при обычном чтении ожидаем. Поэтому после цикла проверяется `!input.eof()`: если чтение прекратилось по другой причине, выводится ошибка. После записи и закрытия проверяется `!output`, чтобы обнаружить проблему вывода.

## 9. Почему ввод целого числа сделан через строку

При обычном `cin >> k` ввод `2.5` может дать целую часть `2`, а оставшиеся символы останутся в потоке. Методичка требует отклонять вещественные значения полностью.

Поэтому `readInt` сначала читает всю строку, затем разбирает её через `stringstream`:

```cpp
stringstream input(readLine(prompt));
int value;
char extra;
if (input >> value && !(input >> extra) && value >= minimum && value <= maximum) {
    return value;
}
```

`stringstream` похож на поток файла, но получает данные из строки в памяти.

Проверки выполняются слева направо:

1. `input >> value` — удалось ли прочитать целое число.
2. `!(input >> extra)` — после числа нет другого непробельного символа.
3. Число входит в разрешённый диапазон.

Для `2.5` после числа остаётся точка, поэтому вторая проверка не проходит. Для `2 abc` остаётся буква. Для `abc` уже первая проверка неудачна. Ввод `2` или ` 2 ` корректен.

`&&` означает «и». Следующая часть проверяется только после успешной предыдущей. Если ввод неверен, цикл запрашивает его заново. Все остальные поля тоже читаются через `getline`, поэтому Ф.И.О. и названия могут содержать пробелы.

## 10. Короткие ответы на контрольные вопросы методички

1. **Как открыть файл и какие есть режимы?** Создать `ifstream`, `ofstream` или `fstream` с именем файла. Основные режимы: `in`, `out`, `trunc`, `app`, `ate`, `binary`.
2. **Как прочитать содержимое?** `>>` для отдельных значений, `getline` для строк, `get` для байтов текста, `read` для блока бинарных данных.
3. **Как записать данные?** `<<` для текстового представления, `write` для байтов из памяти.
4. **Чем отличаются текстовый и бинарный файлы?** Способом представления и чтения данных; текстовый режим также может преобразовывать обозначения конца строки.
5. **Как проверить существование?** Есть `filesystem::exists`. Для работы нужно также убедиться, что файл можно открыть: проверить `is_open()` после создания потока. Существование не гарантирует доступ.
6. **Как переместить позицию?** `seekg` при чтении, `seekp` при записи. Текущая позиция получается через `tellg` и `tellp`.
7. **Как читать и писать бинарные файлы?** Открыть с `ios::binary`, использовать `read` и `write`, передавая адрес памяти и число байтов.

Попробуй без подсказки объяснить, зачем перед вторым чтением нужны `clear()` и `seekg(0)`, почему нельзя сохранить `string` простым `write` всей структуры и откуда берётся формула `(number - 1) * sizeof(Voucher)`. Это основные идеи данной работы.
