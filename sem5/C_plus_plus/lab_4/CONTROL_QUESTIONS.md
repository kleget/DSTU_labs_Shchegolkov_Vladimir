# Ответы на контрольные вопросы лабораторной № 4

В методичке семь контрольных вопросов. Здесь даны ответы на каждый, с примерами. Разбор самой программы находится в [README.md](README.md), теория с нуля — в [THEORY.md](THEORY.md).

Примеры ниже — фрагменты кода внутри функций. Для них используются заголовки:

```cpp
#include <fstream>
#include <iostream>
#include <stdexcept>
#include <string>

using namespace std;
```

## 1. Как открыть файл и какие режимы доступа к файлу существуют?

Файл открывают через файловый поток. Для чтения используется `ifstream`, для записи — `ofstream`, для чтения и записи — `fstream`.

```cpp
ifstream input("text.txt");
ofstream output("result.txt");
```

Открытие происходит при создании потока. Можно также сначала создать поток, затем вызвать `open`:

```cpp
ifstream input;
input.open("text.txt");
```

После открытия нужно проверить `input.is_open()`. Если вернулось `false`, файл открыть не удалось.

| Режим | Назначение |
| --- | --- |
| `ios::in` | Чтение; используется по умолчанию у `ifstream` |
| `ios::out` | Запись; используется по умолчанию у `ofstream` |
| `ios::trunc` | Очистка содержимого существующего файла при открытии |
| `ios::app` | Добавление каждой записи в конец файла |
| `ios::ate` | Переход в конец сразу после открытия; затем позицию можно менять |
| `ios::binary` | Бинарный режим без преобразований текстового режима |

Обычный `ofstream output("result.txt")` создаёт новый файл или очищает существующий. `ifstream` отсутствующий файл не создаёт.

Режимы объединяются через `|`:

```cpp
ofstream output("vouchers.txt", ios::binary | ios::app);
```

В этом примере данные дописываются в конец в бинарном режиме. После работы поток можно закрыть через `close()`. Он также закрывается автоматически при выходе из своей области видимости.

## 2. Каким образом можно прочитать содержимое файла?

Способ зависит от того, какие данные нужны.

| Способ | Что читает |
| --- | --- |
| `input >> value` | Отдельное значение: число или слово; начальные пробельные символы пропускаются |
| `getline(input, line)` | Строку целиком, включая пробелы внутри, но без завершающего перевода строки |
| `input.get(ch)` | Один байт текста, включая пробелы и переводы строк |
| `input.read(address, size)` | Блок байтов заданного размера |

Например, чтение файла по строкам:

```cpp
ifstream input("text.txt");
if (!input.is_open()) {
    throw runtime_error("Не удалось открыть text.txt.");
}

string line;
while (getline(input, line)) {
    cout << line << '\n';
}
```

Условие цикла проверяет, удалось ли прочитать очередную строку. Пустые строки тоже читаются успешно. Писать `while (!input.eof())` вместо проверки самого чтения не следует: конец файла обнаруживается только при попытке чтения, поэтому возможна обработка старого значения.

В нашей работе задание 1 использует `getline`, задание 2 — `get`, задание 3 — `read`. Одна русская буква в UTF-8 может занимать несколько байтов, поэтому в задании 2 они собираются вместе.

## 3. Как записать данные в файл?

Нужно открыть поток `ofstream` и передать ему данные через `<<` для текста или через `write` для блока байтов.

```cpp
ofstream output("result.txt");
if (!output.is_open()) {
    throw runtime_error("Не удалось создать result.txt.");
}

output << "Результат: " << 25 << '\n';
output.close();
if (!output) {
    throw runtime_error("Ошибка записи result.txt.");
}
```

Сначала проверяется открытие, затем — успешность записи и закрытия. Часть данных может временно находиться в буфере, поэтому ошибка способна обнаружиться при закрытии потока.

Чтобы сохранить старое содержимое и дописать новое, нужен `ios::app`:

```cpp
ofstream output("result.txt", ios::app);
output << "Новая строка\n";
```

Бинарная запись через `write` показана в ответе на вопрос 7.

## 4. Понятие текстового и бинарного файлов?

Оба файла на диске состоят из байтов. Разница в том, как программа представляет и обрабатывает данные.

**Текстовый файл** хранит данные как символы в выбранной кодировке. Например, число `123`, записанное через `<<`, представлено символами `1`, `2`, `3`. Такой файл удобно читать в текстовом редакторе.

**Бинарный файл** в этой работе хранит байты структур в том виде, в котором они находятся в памяти. Число `int` записывается своим внутренним представлением размером `sizeof(int)`, а не последовательностью цифр.

Текстовый режим также может преобразовывать обозначения конца строки. Например, в Windows при чтении пара `\r\n` становится `\n`. В бинарном режиме такого преобразования нет.

Расширение имени не определяет режим. Наш `vouchers.txt` имеет расширение `.txt` по требованию методички, но открывается с `ios::binary` и содержит бинарные записи. Само по себе указание `ios::binary` не меняет работу `<<`: для записи байтов структуры используется именно `write`.

## 5. Как проверить существование файла?

В C++17 есть `filesystem::exists`. Для него подключается `<filesystem>`:

```cpp
if (!filesystem::exists("text.txt")) {
    cout << "Файл не существует.\n";
}
```

Эта функция проверяет наличие указанного пути. Существование ещё не гарантирует доступ к данным. Поэтому перед чтением нужно также проверить успешность открытия:

```cpp
ifstream input("text.txt");
if (!input.is_open()) {
    throw runtime_error("Файл не существует или недоступен.");
}
```

`is_open()` подтверждает, что поток открыл файл. Сам по себе отрицательный результат не позволяет отличить отсутствующий файл от файла без доступа.

В нашей программе неудачное открытие вызывает исключение. Блок `catch` в `main` выводит сообщение и завершает программу с кодом `1`, как требуется для отсутствующего исходного файла.

## 6. Как переместить указатель текущей позиции в файле?

Для позиции чтения используется `seekg`, для позиции записи — `seekp`. Текущую позицию можно узнать через `tellg` и `tellp` соответственно.

Можно указать смещение и точку, от которой оно отсчитывается:

| Точка отсчёта | Значение |
| --- | --- |
| `ios::beg` | Начало файла |
| `ios::cur` | Текущая позиция |
| `ios::end` | Конец файла |

Примеры для открытого бинарного потока `file`:

```cpp
file.seekg(0, ios::beg);
file.seekg(5, ios::cur);
file.seekg(0, ios::end);
```

Эти команды по очереди переходят в начало, на пять байтов вперёд от текущей позиции и в конец файла.

Чтобы прочитать запись с порядковым номером `number`, в нашей программе вычисляется её начало:

```cpp
streamoff recordSize = sizeof(Voucher);
file.seekg((number - 1) * recordSize);
```

Все структуры одинакового размера и идут подряд. Первая начинается с байта `0`, вторая — с байта `recordSize`, третья — с байта `2 * recordSize`. Номер записи здесь — её место в файле, а не поле «номер путёвки».

Если ранее достигнут конец файла, перед повторным чтением нужно сбросить состояние потока:

```cpp
file.clear();
file.seekg(0);
```

`clear()` сбрасывает флаги ошибок и конца файла, а содержимое файла не меняет.

## 7. Как писать и читать бинарные файлы?

Файл открывают с `ios::binary`. Запись выполняется через `write`, чтение — через `read`. Обоим методам передаются адрес памяти и количество байтов.

В примере `voucher` — заполненная структура `Voucher`, описанная в `main.cpp`:

```cpp
ofstream output("vouchers.txt", ios::binary);
if (!output.is_open()) {
    throw runtime_error("Не удалось создать vouchers.txt.");
}
output.write(reinterpret_cast<const char*>(&voucher), sizeof(Voucher));
output.close();
if (!output) {
    throw runtime_error("Ошибка бинарной записи.");
}

ifstream input("vouchers.txt", ios::binary);
if (!input.read(reinterpret_cast<char*>(&voucher), sizeof(Voucher))) {
    throw runtime_error("Не удалось прочитать полную запись.");
}
```

Разбор аргументов:

| Выражение | Значение |
| --- | --- |
| `&voucher` | Адрес структуры в памяти |
| `reinterpret_cast<const char*>(...)` | Представление этого адреса как адреса байтов для записи в файл |
| `reinterpret_cast<char*>(...)` | Представление адреса как адреса байтов, которые можно изменить при чтении |
| `sizeof(Voucher)` | Полный размер структуры в байтах |

`write` копирует байты из памяти в файл, `read` — из файла в память. Если `read` не получил полный запрошенный блок, проверка в `if` обнаружит неудачу.

Так можно сохранять наши структуры с полями `char[]` и `int`. Поля `char[]` содержат сам текст внутри структуры. Объект `string` может хранить указатель на отдельную память: простая запись байтов объекта не сохранит текст по этому указателю, поэтому здесь он не используется.

Бинарный файл такого формата рассчитан на чтение программой с тем же устройством структуры и представлением типов. Поэтому размер берётся через `sizeof(Voucher)`, а не складывается вручную: компилятор может оставлять промежутки между полями.

В лабораторной методы `VoucherList::save` и `VoucherList::load` работают со всеми записями, а `VoucherList::readOne` сначала переходит к нужному месту через `seekg` и читает только одну запись.
